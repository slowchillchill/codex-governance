# 工程任务与交付编排

## 接单与职责

用户显式调用本 Skill 并给出明确开发需求，或本组接受有效工程委托，且目标仓库根 `AGENTS.md` 已接入时，才启动开发流程。先判断启用条件，再核验身份和查询任务；未启用时按当前请求处理，不因读取规则启动工程闭环。已有交付的澄清与继续执行沿用原授权，不选择范围外任务。

本组负责准确工程合同的规划、实现、必要验证、独立技术审查、提交推送、PR 维护、合并与收尾。交回准确版本、变更语义、使用入口、验证和限制；不把工程通过写成研究结论或业务目标达成。命令权限不扩大任务、身份或破坏性操作授权。

## 规则路径与执行

解析本 `SKILL.md` 的真实文件路径，以所在目录解析下列相对链接。先读本源[治理规范](../../governance/codex-development-governance.md)的“启用条件与当前请求边界”，确认接单后读“本机配置与规则定位”和“身份核验与命令归属”。规则缺失时报告缺口，不猜另一副本。

本机公共绑定取非空 `CODEX_GOVERNANCE_CONFIG`，否则 `${XDG_CONFIG_HOME:-$HOME/.config}/codex-governance/local.toml`。以 `paths.source_root` 定位通用原则、交接协议和 `scripts/group_github.py`；平台及远端 Git 命令使用 `--group development` 和本组绑定，先核验实际身份，缺失或不符时停止相关操作，不借用其他身份。

开发内部流程只按治理规范执行：第二节确定准确任务与交付范围，第三节读取工程原则，第四节规定本组角色，第五节恢复状态，第六节规定规划、实现、审查与交付，第七节规定授权。需要具体操作时读取[编排程序](references/stage-procedure.md)，清理前读取其第五节；入口不复制内部步骤。

## 对外交接

接收委托、请求创建 PR、返回结果或恢复跨组任务时，读取公共源的 `governance/group-collaboration.md`。委托必须保留准确 Issue、原授权、范围、验收、预计成本、同一阶段预算和固定回传入口，由本组核对并明确接受。查询、材料和通知不构成新任务授权。

验证、推送后向实际签发方交回分支、完整提交、PR 材料，取得 PR 链接后继续本组交付；最终结果与困难固定返回实际签发方。按接单合同执行工程验收，输入缺口或需要改变合同的事项返回获授权的裁决者。本组不接管对方的实验、结论、业务采用或监督流程。

`agents/openai.yaml` 保持 `allow_implicit_invocation: false`。Skill 不切换 Profile、模型或命令权限；本组不使用 `/goal`、后台轮询或其他治理工具推进任务。
